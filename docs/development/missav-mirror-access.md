# MissAV 镜像访问

MissAV 在 Cloudflare 验证下可能无法直接读取。匿名访问和会话待确认时，应用使用匿名镜像站，并保留官方备用域名回退；确认登录后，自动模式优先 `missav.ai`。
方案参考 [HANiEX](https://github.com/lwprfs/HANiEX) 的 MissAV 主机列表和 Recombee 搜索。

## 访问顺序

1. 公开内容首屏不等待账号恢复。手动选择镜像时，应用先请求该镜像；自动选线且会话未登录、待确认或失效时，应用使用镜像。
2. 确认登录后，自动模式的新请求优先 `missav.ai`。从镜像卡片打开详情时，卡片所在线路仍先参与候选。
3. 请求失败或首条镜像变慢时，按 [ADR 0012](../adr/0012-missav-content-host-cache.md) 的换线、1.5 秒加发和总时限规则处理。`missav.live` 和 `missav.ws` 仅作公开内容回退。

页面通过检查后才更新当前线路。只有通过检查的镜像页面可以更新上次可用内容线路。手动选择只在遇到 Cloudflare 验证时清除。换线条件和页面检查规则见 [ADR 0012](../adr/0012-missav-content-host-cache.md)。

镜像站会把 `/cn` 等路径重定向到 `/dmNNN/...`。
现有地址处理保留该前缀，后续分页和详情链接沿用同一路径。
视频页直接请求第一页。后台测速见[后台测速与账号线路](#后台测速与账号线路)。

## 搜索

搜索直接请求 Recombee，不先读取镜像页面。只有请求失败或响应无效时，搜索才回退到镜像页面。Recombee 成功返回空结果时，搜索显示无结果，不使用镜像卡片。

```text
POST https://client-rapi-missav.recombee.com/missav-default/search/users/anonymous/items/
```

请求体使用 `searchQuery`、`scenario: "search"` 和 `returnProperties: true`。
后续页使用返回的 `recommId` 调用 `recomms/next/items/{recommId}`。
已访问的搜索页只保存在内存中，返回上一页不会继续推进游标。同一页的并发请求共用一次续页请求。新搜索、账号会话或语言变化后，应用重新建立分页状态。回退后的上一页和下一页均沿用镜像链接，重新搜索时再尝试 Recombee。

同一续页还有调用在等待时，应用保留共享请求。所有调用都取消且请求仍在执行时，应用取消共享请求。再次打开该页时使用镜像分页，避免复用可能已推进的游标。过期响应不会覆盖新搜索的分页状态。

## 播放与下载

镜像站详情页把媒体地址改写为 `https://<镜像站>/jmpres/<原始主机>/<路径>`。
应用解析打包脚本后执行同样的改写。
播放器直接打开原 HLS 地址，由原生播放器处理跳转。
首帧对照结果见 [ADR 0013](../adr/0013-missav-verification-and-playback-recovery.md)。
播放器和下载器收到的请求头使用镜像站页面作为 `Referer` 和 `Origin`。
镜像 HLS 的分段文件名为 `.jpeg`，内容是 MPEG-TS。
项目使用的 mpv 已为 FFmpeg HLS 设置 `extension_picky=0`，下载端把分段保存为 `.ts`。
播放器保留 media_kit 的 `demuxer-lavf-o` 原值，其中 `protocol_whitelist` 是包含逗号的单个值。
将该属性的字符串结果整串写回会拆坏协议白名单，使 HTTPS 媒体加载失败。

Android 播放流使用现有 `native_audio` 通道获取系统证书文件。
原生播放器在打开播放流前设置 `tls-ca-file`，保留证书和主机名校验。

`test/videos/video_native_stream_host_test.dart` 使用真实 libmpv 加载本地多级 HLS 清单和 `.jpeg` 分段。
该测试要求解码完成且播放器未报错，已接入 Windows 正式版和测试版构建检查。
Windows 宿主测试还模拟 Android 证书通道，覆盖可信证书播放和错误主机名拒绝。

## 账号 Cookie

MissAV 的账号线路只有 `missav.ai`。`missav.live` 和 `missav.ws` 只用于公开内容回退，不接收账号 Cookie。
账号 Cookie 只发送给会话绑定的账号线路。
登录、收藏、播放列表和观看历史使用同一源站账号态。
镜像响应不写回源站会话，避免覆盖本地 Cookie。

MissAV 与 Jable 共用账号页和登录流程。

1. 在 MissAV 账号页选择**登录**。账号页不显示账号线路选择。
2. 在应用内网页完成登录及站点要求的验证。
3. 选择**完成**。应用在 `missav.ai` 确认并保存会话。

应用只恢复明确绑定 `missav.ai` 的会话。旧会话缺少线路记录或绑定了其他线路时，需要重新登录。
收藏、播放列表、观看历史或恢复检查遇到视频源验证时，账号页提供**验证访问**。

需要媒体转发时，播放或下载才启动转发。启动失败时可重试对应操作。
关闭媒体转发后，账号会话仍可用。切换账号时，应用关闭原账号的媒体转发。
视频播放列表和视频观看历史通过账号线路加载。视频播放列表封面沿用内容线路。
演员收藏和视频播放列表条目可以不带 `main` 容器，解析时按演员或播放列表卡片处理。
从镜像卡片打开详情时，先请求该卡片的镜像地址，再按内容线路回退。
账号集合中的详情在内容线路返回 404 或 410 后，回退到账号线路。
已登录或有待确认会话时，镜像详情从账号线路读取收藏状态。账号线路要求验证或登录时，详情仍可显示，收藏状态保持未知。

## 后台测速与账号线路

自动选线且会话未确认时，下一次公开内容请求优先使用本轮测速中响应最快的可用线路。没有可用测速结果时，目录先请求上次可用内容线路，没有记录则请求默认线路。从镜像卡片打开详情时，卡片所在的线路仍可作为候选。没有可用测速结果时，先请求卡片所在的线路。匿名详情采用 1.5 秒加发规则。确认登录后，自动模式的新请求优先 `missav.ai`；手动选择镜像时仍按手选线路。

自动选线时，视频页空闲 1 秒便可开始测速。会话待确认时，测速与恢复检查并行；首屏内容不等待两者。每轮复用现有测速器，最多测 3 条内容线路，优先纳入上次可用内容线路，再按默认顺序补足。同一时间只测 1 条。每次应用运行完成 1 轮测速。开始加载视频详情时取消测速，返回空闲视频页后可重新安排。

已发起的请求使用开始时的候选顺序。测速选出的首选线路发生故障时，按内容线路回退规则尝试其他线路。真实内容请求通过检查后，才更新上次可用内容线路。目录响应时间用于估计线路响应速度。

应用将会话绑定到 `missav.ai`。收藏、播放列表和观看历史在重启后继续使用该账号线路。公开内容按内容线路选择。

真机验收覆盖有无上次可用内容线路，以及首条线路正常和变慢的情况。记录从点击到首个可见画面的总耗时。分段记录从点击到取得播放流、从打开播放流到画面出现的耗时。对比视频首帧等待的 P50、P95 和出画成功率。
