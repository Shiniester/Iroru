# MissAV 内容线路缓存与官方线路回退

## Status

Accepted

## Context

MissAV 内容页优先使用第三方镜像。目录请求失败时会换线，详情请求失败时会直接结束。镜像返回 HTTP 200 的占位页也可能覆盖上次可用内容线路。

## Decision

目录、视频详情、播放列表封面和首页推荐共用内容线路恢复规则。应用先尝试手动选择的线路，再尝试上次可用内容线路。其余镜像按实测顺序逐条尝试。镜像因线路故障全部失败后，应用按 `missav.live`、`missav.ws`、`missav.ai` 的顺序尝试官方线路。

网络错误、超时、HTTP 5xx、Cloudflare 验证和无效页面触发换线。取消请求、会话或语言变化、HTTP 401、404、410 和 419 直接结束请求。

目录、播放列表封面和首页推荐页面需要包含 `<main>`。空目录有效。视频详情还需要有标题或可解析的播放流。

每次请求使用自己的候选线路。页面通过检查后才更新当前线路。只有通过检查的镜像页面可以更新上次可用内容线路。上次可用内容线路发生线路故障时清除缓存。手动选择的线路发生线路故障时允许临时换线，只有遇到 Cloudflare 验证时才清除选择。

账号登录和账号接口使用独立的官方线路。只有官方线路的验证错误显示验证入口。内容线路恢复不会自动打开隐藏浏览器。视频详情根据加载该详情的线路判断是否请求账号状态。详情发布后的补充请求失败不会换线。

## Consequences

视频页直接请求第一页。应用不单独测速，不并行尝试线路，也不保存页面内容。首选线路可用时无需发起回退请求。所有镜像因线路故障失败时仍可能需要视频源验证。
