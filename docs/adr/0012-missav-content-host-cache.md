# MissAV 内容线路缓存与官方线路回退

## Status

Accepted

2026 年 11 月 17 日确认时限和详情缺失规则。

## Context

MissAV 内容页优先使用第三方镜像。镜像目录和视频详情可能使用 `<div>` 容器，不包含 `<main>`。应用需要区分可用页面与 HTTP 200 占位页，避免无效换线或覆盖上次可用内容线路。

## Decision

目录、视频详情、播放列表封面和首页推荐共用内容线路恢复规则。应用先尝试手动选择的线路，再尝试上次可用内容线路。其余镜像按实测顺序逐条尝试。镜像因线路故障全部失败且仍有剩余时间时，应用按 `missav.live`、`missav.ws`、`missav.ai` 的顺序尝试官方线路。
从镜像卡片打开视频详情时，先请求卡片所在镜像的地址；从账号页面打开时按内容线路规则尝试。

每次内容页加载的总时限初设为 12 秒，涵盖重定向和换线。单条线路最多用 4 秒，以剩余时间为上限。总时限到达时，应用取消仍在执行的请求。单条线路超时后，应用在剩余时间内继续换线。总时限耗尽时，目录和视频详情页提供**重试**和**在源站打开**。调试日志记录每次加载实际尝试的线路数，供调整时限时参考。

网络错误、超时、HTTP 5xx、Cloudflare 验证和无效页面触发换线。调用方取消、会话或语言变化、HTTP 401 和 419 直接结束请求。目录、播放列表封面和首页推荐返回 HTTP 404 或 410 时，结束请求。视频详情返回 HTTP 404 或 410 时，视为该线路缺少当前视频。在剩余时间内继续回退，候选线路包括卡片原地址和账号线路。

目录、播放列表封面和首页推荐页面需要包含 `<main>`，或能解析出视频卡片。包含 `<main>` 的空目录有效。视频详情包含可解析播放流时，不要求包含 `<main>`。没有播放流时，详情仍需包含 `<main>` 和非空标题。

每次请求使用自己的候选线路。页面通过检查后才更新当前线路。只有通过检查的镜像页面可以更新上次可用内容线路。详情缺失时保留上次可用内容线路。确认该线路发生线路故障时清除缓存。手动选择的线路发生线路故障时允许临时换线，只有遇到 Cloudflare 验证时才清除选择。

账号登录和账号接口使用独立的官方线路。只有官方线路的验证错误显示验证入口。内容线路恢复不会自动打开隐藏浏览器。视频详情根据加载该详情的线路判断是否请求账号状态。详情发布后的补充请求失败不会换线。

关键词搜索直接请求 Recombee。只有请求失败或响应无效时，搜索才使用内容线路恢复。成功返回空结果和取消请求均不触发镜像回退。已访问的搜索结果只保存在内存中，用于返回上一页。

2026-11-18 修订：视频详情页确认离页或替换视频时，取消当前详情和推荐请求。取消不触发换线，也不显示加载失败。切换底部页签、退后台和取消返回手势不取消请求。

2026-11-18 修订：公开目录翻回已访问分页时，应用复用内存中的页面，不再请求源站。页面按内容线路最终地址识别。这个复用只发生在同一视频页会话内。手动重进目录、重试和账号集合仍按源站刷新。

2026-11-18 修订：未登录且使用自动选线时，视频详情可以加发镜像请求。首条镜像请求等待 1.5 秒仍未完成时，应用请求下一条镜像。两条请求共用同一次详情加载的总时限。应用采用先返回可解析播放流的详情，并取消另一条请求。应用根据选中的详情更新线路缓存。如果两条都没有可解析播放流，应用保留先通过详情检查的页面。如果两条都失败，应用逐条尝试剩余线路。

## Consequences

视频页直接请求第一页，后台测速结果用于后续自动选线。详见[后台测速与账号线路](../development/missav-mirror-access.md#后台测速与账号线路)。应用不把页面内容保存到磁盘。符合加发条件的详情加载最多同时请求 2 条镜像线路。所有镜像因线路故障失败时仍可能需要视频源验证。翻回已访问的公开分页时，应用可能显示该会话的缓存内容。

总时限可能在应用尝试到可用线路前耗尽。根据加载成功率、加载耗时和实际尝试的线路数调整初始时限。
