# MissAV 视频源验证、首播与媒体转发

## Status

Accepted

2026 年 11 月 17 日确认。
2026 年 11 月 21 日确认账号恢复、内容线路和媒体转发的边界。

## Context

普通 HTTP 403 可能触发视频源验证。HLS 预解析会延迟播放器打开播放流。关闭媒体转发可能中断账号访问。

## Decision

### 视频源验证

账号功能或恢复检查收到已确认的视频源验证时，账号页提供**验证访问**。用户选择后打开验证窗口。应用内验证失败时，提供**在源站打开**。网页登录流程见 [ADR 0005](0005-native-video-and-source-account.md#2026-11-21-修订)。

优先按 `cf-mitigated: challenge` 确认验证，缺少响应头时使用已知的验证页标记。对普通 HTTP 403 显示拒绝访问。收到 HTTP 429 时结束本次提交。响应包含有效的 `Retry-After` 时，提示用户何时可重试。依据见 [Cloudflare 验证页响应说明](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)和 [RFC 6585 第 4 节](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)。

### 视频首帧等待

打开 MissAV 视频详情页时，应用先检查本地下载，再在入场动画期间请求在线详情。应用在动画结束后显示详情并打开播放流。应用在首次打开播放器或显示在线加载错误前重新检查本地下载。用户确认离页时，应用取消请求。

如果入场动画结束后仍在等待在线详情，应用先初始化播放会话。视频播放器在收到播放流后复用该会话。详情加载失败或用户确认离页时，应用释放未接管的会话。

视频播放器直接打开 HLS 原地址，由原生播放器处理跳转。Windows 本机对照使用同一份 H.264 样本，由本机 HTTP 服务器提供清单和分段。

| 首播路径 | 解码首帧成功 | 首帧耗时第 95 百分位 | 清单请求数（含跳转） |
| --- | ---: | ---: | ---: |
| 直开原地址 | 20/20 | 66.60 毫秒 | 60 |
| 预解析后打开 | 20/20 | 75.01 毫秒 | 80 |

计时从打开地址或预解析开始，到无窗口 libmpv 报告首个已解码视频帧。真机上的可见首帧等待仍待测量。样本来自 [FFmpeg FATE](https://fate-suite.ffmpeg.org/mpegts/)。

### 媒体转发

播放或下载需要媒体转发时，应用才启动转发。启动失败时提供**重试**，由对应的播放或下载操作重新启动转发。关闭媒体转发时保留可用的账号会话。源站明确要求验证时，显示**验证访问**。

退出或切换视频源账号时，应用关闭旧账号的转发并丢弃迟到的结果。验收时模拟转发启动失败和关闭转发，确认收藏仍可读取。模拟准备转发时切换账号，确认迟到的结果会被丢弃。

账号页没有保存的会话时，显示**登录**。存在保存会话时，账号页先显示**正在恢复登录**。MissAV 的恢复检查只使用 `missav.ai`。账号页、收藏、播放列表和观看历史共用同一次恢复检查；并发调用等待同一结果。

公开内容首屏不等待恢复检查。确认前，内容继续使用镜像；恢复检查不接管内容线路，也不启动媒体转发。内容线路选择见 [ADR 0012](0012-missav-content-host-cache.md)。

网络或源站暂时不可用时，账号页保留会话并提供**重试**。遇到视频源验证时，账号页提供**验证访问**。从视频详情页触发恢复失败时，应用打开账号页。会话失效或未绑定 `missav.ai` 时，应用要求重新登录，自动模式回到镜像。主动退出账号时，应用清除会话并丢弃迟到的检查结果。

应用将源站更新的 Cookie 写入安全存储。原生响应提供到期时间时，应用一并保存，并在发送请求时跳过已过期的 Cookie。会话 Cookie 只发送给 `missav.ai`。旧会话的恢复条件见 [ADR 0005](0005-native-video-and-source-account.md#2026-11-21-修订)。验证窗口导入的会话也由 `missav.ai` 确认。

视频源验证通过后，如果账号状态仍未确认，账号页使用保存的会话再检查一次。确认登录后，账号页显示账号信息。

播放换流时，最新请求取消旧流的媒体准备。旧任务只完成已开始的会话操作，不再执行后续设置和播放。自动播放与自动画中画准备同时启动，加载流程不等待画中画完成。

### Windows 播放启动测量

2026-11-18 在 Windows 本机 Debug 构建中运行 3 次测量，重复 2 轮。样本为 2.87 MB MP4，由本机 HTTP 服务器提供。计时从播放器组件挂载开始，到 libmpv 报告首个已解码视频帧。

| 轮次 | 样本 1 | 样本 2 | 样本 3 |
| --- | ---: | ---: | ---: |
| 1 | 1678 毫秒 | 618 毫秒 | 569 毫秒 |
| 2 | 1564 毫秒 | 954 毫秒 | 651 毫秒 |

6 个样本的中位数为 803 毫秒。首个样本包含 MediaKit 初始化，耗时 1564～1678 毫秒；后续样本为 569～954 毫秒。该指标是解码首帧，不是可见首帧。样本来自本机临时文件，不代表 MissAV 网络或真机表现。

## Consequences

源站要求验证时，用户多一次点击。首次需要媒体转发时，播放或下载要等待转发就绪。
